# 自指回路七层稳定性设计审视报告

> 审视基准：以 `runtime/loop.py`、`core/hippocampus/*`、`core/meta/meta_plasticity.py`、`bridge/encoder.py`、`bridge/decoder.py`、`persistence/snapshot.py` 的实际源码为锚点，逐条验证设计的可落地性与潜在冲突。本报告不客气。

---

## 一、现状核实：自指回路尚未实现，且现有架构无任何回路隔离设施

经全仓搜索（`self_ref|自指|feedback|loop_back|echo|novelty`），**项目当前不存在自指回路的任何实现**。`process_turn` 的数据流是单向的：

```
encode(user+llm) → infer → learn → 熵管理 → purpose.adjust → memory.update/consolidate → recall → decode → return memory_context
```

`memory_context`（Decoder 输出）直接返回给调用方（`query_llm` 或 API），**没有任何路径将其回注到 Encoder**。因此七层设计是"从零新建"，不是"改造既有回路"。这一点直接影响下文的架构判断。

---

## 二、逐层评分与具体漏洞

### 第一层：反馈幅度阻尼（自指 0.3 / 外部 1.0）—— 评分 5/10

**设计意图**：自指输入权重 0.3，外部输入权重 1.0，确保外部信号主导。

**源码核实的漏洞**：

1. **"权重"的语义未定义，且与 precision 耦合导致实际放大不可控**。
   `attractor.infer()` 的 clamping 公式是（`attractor.py:213`）：
   ```python
   b_q[:input_dim] = b_q[:input_dim] + sensory_input * precision
   ```
   如果"自指权重 0.3"实现为 `sensory_input = 0.3*self_ref_vec + 1.0*external_vec`，那么自指的实际贡献是 `0.3 * self_ref_vec * precision`。而 `precision_max = 10.0`（`config.py:85`），意味着自指项的最大幅度可达 `0.3 * 10 = 3.0`，而外部项最大也是 `1.0 * 10 = 10.0`。表面是 0.3:1.0，实际经 precision 放大后仍是 0.3:1.0（比例不变），**但当外部输入为零或极小时（空用户输入、LLM 输出为空），0.3 的自指成为唯一信号**。设计未覆盖"外部输入缺失"这一常见边界。

2. **Hebbian 学习对自指的间接放大未计入**。
   `learn()` 中 `hebbian = torch.outer(sigma, sigma)`（`attractor.py:321`），sigma 是被自指影响的激活态。即使自指权重 0.3，只要它改变了 sigma 的收敛方向，J 矩阵就会沿自指方向强化。**0.3 的阻尼只作用于推断的 clamping，不作用于学习的 Hebbian 项**。多轮累积后，自指方向的 J 强化会逐步降低对该方向的实际阻尼——这是指数级慢漂移的根源。

3. **正交化压力反而保护自指吸引子**。
   `_complexity_gradient` 的 saturation 门控（`attractor.py:397`）：`orth_pressure = orth_weight * saturation * |Hebbian|`。当自指方向被反复强化后，该方向的 J 饱和度高，新外部输入在自指方向的学习被抑制，而自指自身的 Hebbian 也在该方向被抑制——表面看是双向抑制，**但自指每轮都来，外部输入是偶发的，净效果是自指方向被"锁定"而外部被"排斥"**。0.3 的初始阻尼被正交化机制间接瓦解。

4. **参数 0.3 是魔法数字，无数学依据**。未给出相对于 `temperature=0.05`、`precision_lr=0.1`、`learning_rate=0.01` 的联合稳定性分析。

### 第二层：新颖性门控（差异超阈值才反馈）—— 评分 3/10

**设计意图**：decoder 输出与上一轮自指输入差异超过阈值才反馈，避免重复回声。

**漏洞**：

1. **类型不一致：比较的是文本还是向量？** Decoder 输出是结构化文本（`decoder.py:140` 起：`"[记忆context]\n记忆状态解读:\n- ..."`），而"上一轮自指输入"是感官向量。要比较必须先重新编码 decoder 文本。**但重新编码后的向量代表的是"context 文本结构"，不是"语义内容"**——每轮 decoder 输出的文本骨架几乎相同（都是 `[记忆context]\n记忆状态解读:` 开头），只是数值不同。用文本 embedding 算差异，差异主要来自数值字符串，而非语义。这个门控几乎永远不会触发"低差异"，因为浮点数尾数每轮都变。

2. **对振荡完全无效**。新颖性门控只阻断"重复"，不阻断"振荡"。若系统在状态 A 和 B 之间交替，每轮差异都很大，门控全部放行——振荡被完整传递。

3. **对慢漂移过度敏感**。若系统缓慢漂移，每轮差异略低于阈值，门控持续阻断，自指回路被静默切断。用户不会收到任何错误提示，只是"自指功能消失了"。

4. **阈值无标度**。L2 范数？余弦？若是 L2，量纲依赖 `input_dim=64`；若是余弦，结构化文本的余弦相似度天然很高（骨架相同），阈值需要极接近 1.0 才有意义。设计未指定。

5. **与延迟反馈（第六层）的语义冲突**。若延迟 N 轮，"上一轮自指输入"是指 T-1 轮的，还是 T-N 轮的？设计未说明。若比较 T 轮的 decoder 输出与 T-N 轮的自指输入，时间错配使新颖性信号失真。

### 第三层：习惯化作为天然阻尼 —— 评分 6/10（机制已存在，但复用代价被低估）

**设计意图**：自指维度反复激活时 precision 降低。

**源码核实**：习惯化已在 `purpose.py:321-334` 实现：
```python
self.encounter_count += (activation.state[:input_dim].abs() > self.activation_threshold).float()
habituation = 1.0 / (1.0 + self.encounter_count * self.habituation_rate)
per_dim_surprise = per_dim_surprise * habituation
```

**漏洞**：

1. **习惯化不区分"自指激活"与"外部激活"**。`encounter_count` 统计的是该维度被显著激活的总次数，无论激活来自自指还是外部。若自指反复激活维度 i，维度 i 的 precision 下降——**但外部输入若也激活维度 i，外部信号同样被衰减**。这是"自指污染外部信任度"的信息泄露，设计未提及。

2. **encounter_count 单调递增，无遗忘机制**。`habituation = 1/(1 + count*0.05)`：count=20 时 0.5，count=200 时 0.09，count=1000 时 0.02。长期运行后，**所有高频维度的 precision 趋近 `precision_min=0.1`**，系统感官信任度全局坍缩。元目的翻转（`_meta_adjust`）只重置一个维度到 max，杯水车薪。这个"天然阻尼"在长时程下会杀死整个感官系统，不只是自指。

3. **activation_threshold=0.3 与自指幅度的关系未验证**。自指权重 0.3 经 precision 放大后，感官节点的 `|σ_i|` 能否稳定超过 0.3？若自指幅度过小（例如 precision 也被习惯化拉低），`|σ_i| < 0.3`，则 encounter_count 不增长，习惯化机制根本不触发——第三层失效，且静默失效。

4. **与第一层的叠加效应**。第一层已将自指阻尼到 0.3，第三层再通过习惯化降低 precision。双重阻尼的乘积效应可能使自指在 50-100 轮后完全失去信号——自指功能名存实亡。

---

### 第四层：熵逃生阀（coherence > 0.95 注入噪声）—— 评分 2/10

**设计意图**：coherence 超过上阈值时强制注入噪声，打破锁定。

**严重漏洞**：

1. **触发信号概念错位**。`coherence` 在 `purpose.py:162` 的定义是"precision 与近期历史的吻合程度"，衡量的是**目的层的稳定性**。高 coherence = precision 稳定 = 目的明确，这是**健康状态**。现有系统用 **低** coherence（< 0.5）触发元目的翻转（`purpose.py:358`）。设计却用 **高** coherence（> 0.95）触发噪声注入——这与既有语义完全相反。若自指锁定导致 precision 稳定（高 coherence），设计者的直觉是对的，但**这个信号无法区分"健康稳定"与"自指锁定"**，一刀切注入噪声会破坏正常记忆巩固后的稳定态。

2. **"注入噪声"注入到哪里？未定义**。是注入 sigma？J？sensory_input？precision？不同位置效果天差地别。`dream_engine.py:718` 的 `_inject_perturbation` 同时扰动 sigma（×0.3）和 J（×0.01），但那是做梦引擎的坍缩恢复，不是在线逻辑。在线注入 J 噪声会直接污染正在学习的 J 矩阵。

3. **与既有"在线熵管理"直接冲突**。`loop.py:294-309`：
   ```python
   if entropy_ratio > entropy_high_threshold (0.9):
       self.attractor.learn(..., orth_weight_override=self.attractor.orth_weight * 1.5)  # 增强正交化，降低熵
   ```
   既有逻辑：熵高 → 增强正交化 → **降低**熵。
   第四层：coherence 高 → 注入噪声 → **提高**熵。
   若某轮同时满足 entropy_ratio > 0.9 且 coherence > 0.95（精度稳定但激活分散，完全可能），一个机制降熵、一个机制升熵，**直接对冲**。设计未讨论谁优先。

4. **0.95 阈值几乎不可达**。`_compute_coherence` 返回的是方向分量（余弦映射到 [0,1]）与幅度分量（范数比值）的加权平均。长期运行中，幅度分量因习惯化持续变化，coherence 很难稳定在 0.95 以上。这个逃生阀可能永远不触发——成为死代码。

---

### 第五层：做梦作为复位（DreamEngine 运行时断开回路）—— 评分 7/10（机制天然成立，但瞬态未处理）

**源码核实**：`DreamEngine` 不调用 `process_turn`，而是直接调用 `_idle_infer` / `_idle_learn` / `memory.update` / `purpose.adjust`。若自指回路实现在 `process_turn` 内，则做梦期间天然断开。

**漏洞**：

1. **断开是天然的，但恢复不是**。做梦会修改 J（NREM 巩固、SHY 归一化、景观漂移）、precision（目的演化、元目的翻转）、memory 潜变量（巩固、遗忘修剪）。做梦结束后，自指回路恢复时面对的是一个**已变化的网络**。若第六层的延迟缓冲区里还存着做梦前的 decoder 输出，这些输出对当前网络而言是"过时的外来信号"——可能触发意外的大 surprise，引发学习风暴。

2. **DreamEngine 内部调用 `purpose.adjust`**（`dream_engine.py:671`），这会更新 `encounter_count` 和 `history`。若自指的"习惯化"基于 encounter_count，做梦期间 encounter_count 被离线回放驱动增长，**做梦在暗中消耗了第三层的阻尼预算**——醒来后自指维度可能已被习惯化到失效。

3. **做梦的 `_forgetting_pruning` 会清理情景缓冲区**（`dream_engine.py:614`）。若自指生成的文本被存入情景缓冲区（见第六节冲突分析），做梦可能删除自指记忆，造成回路"失忆"。

4. **没有显式的"回路断开标志"**。若未来自指回路需要在做梦期间执行某些清理（如清空延迟缓冲区），目前没有回调钩子。

---

### 第六层：延迟反馈窗口（N=3-5 轮前的输出）—— 评分 5/10

**设计意图**：用 N 轮前的 decoder 输出而非当前轮，解耦即时反馈。

**漏洞**：

1. **启动冷启动问题**。前 N 轮没有延迟输出。设计未定义填充策略（零向量？跳过？用当前轮？）。零向量会注入虚假的"沉默信号"；跳过则前 N 轮无自指；用当前轮则退化为无延迟。

2. **延迟输出与当前网络的状态错配**。N 轮前的 decoder 输出是基于当时的 J、precision、memory 生成的。经过 N 轮学习（含元可塑性每 10 轮调整一次参数），当前网络可能已面目全非。将旧输出重新编码注入，相当于给当前网络输入一个"它不认识的外来信号"——surprise 偏高，触发额外学习。**延迟本应降低自指的耦合强度，但状态漂移可能反而放大 surprise，增强学习**，与设计意图相反。

3. **缓冲区未纳入持久化**。`save_state`（`loop.py:435`）保存 attractor/purpose/memory/tokenizer/meta，**不包含自指延迟缓冲区**。快照恢复后，延迟缓冲区清空，自指回路经历第二次冷启动——且这次是在一个已学习的网络上，冷启动注入的零向量或空信号会扰动已稳定的 J。

4. **N=3-5 的选择无依据**。`consolidation_interval=5`，`meta_interval=10`。若 N=5，延迟恰好与巩固周期对齐，自指输入每次都在巩固后注入，可能形成"巩固-注入-巩固"的共振。设计未分析这种周期对齐效应。

---

### 第七层：惊讶度门控（surprise≈0 只编码不学习）—— 评分 2/10

**设计意图**：surprise 接近 0 时只编码不学习，防止过度强化。

**严重漏洞**：

1. **surprise 的量纲与"接近 0"的判定**。`_compute_free_energy`（`attractor.py:408`）返回的是 `corr_term + bias_term + accuracy + complexity`，**可以是负值**（高共激活时 corr_term 为负）。"surprise≈0"在数学上意味着自由能恰好为零，但这不是一个有意义的"无意外"判据——自由能为 -5 和 +5 都不是"0 意外"，而自由能为 0 可能恰好是能量项与复杂项的抵消。**没有归一化的 surprise 阈值是无意义的**。

2. **与元可塑性的三重叠加冻结**。自指锁定 → surprise 下降 →：
   - 第七层：surprise≈0 → 跳过 learn（冻结 J）
   - 元可塑性：surprise 趋势下降 → `lr_multiplier < 1`（`meta_plasticity.py:357`，`normalized_trend < 0` → target < 1.0）→ 学习率进一步降低
   - 第三层：encounter_count 增长 → habituation 降低 precision → 感官信任降低
   
   三重机制同时生效，系统进入**深度冻结**。第七层阻止 J 更新，元可塑性降低学习率，习惯化降低 precision。**没有任何一层提供"解冻"机制**。第四层的噪声注入本可解冻，但如前述，coherence > 0.95 几乎不可达。

3. **"只编码不学习"的语义模糊**。`infer()` 会更新 `self.sigma`（`attractor.py:230`）。即使跳过 `learn()`，sigma 已被自指输入改变。下一轮的 infer 从被污染的 sigma 出发——**编码本身就污染了状态**，跳过 learn 并不能阻止自指影响传播。

4. **surprise≈0 恰恰是自指锁定的信号，此时跳过学习等于"锁定当前状态"**。第七层的逻辑是：不意外 → 不学。但在自指场景，不意外意味着"系统完全预测了自己的输出"，这正是死循环的稳态。跳过学习 = 保护这个死循环稳态不被打破。**第七层不仅不能防止自指死循环，反而会加速其稳态固化**。

## 三、层间交互问题

### 3.1 第一层 × 第三层：双重阻尼导致自指功能慢性死亡

第一层将自指权重降至 0.3，第三层通过习惯化降低 precision。两者乘积效应：

```
有效自指贡献 ∝ 0.3 × habituation(count) × precision_max
            = 0.3 × 1/(1 + count×0.05) × 10
```

- count=0：3.0
- count=40：1.0
- count=200：0.43

约 40 轮后，自指的有效贡献已降至与噪声同级。**七层设计在"防止自指失控"和"让自指有意义"之间没有平衡点**——所有层都在压制自指，没有一层在维持自指的信号强度。

### 3.2 第二层 × 第六层：新颖性信号的时间错配

若第六层延迟 N 轮，第二层比较的"上一轮自指输入"是 T-1 轮的还是 T-N 轮的？

- 若比较 T 轮 decoder 输出与 T-1 轮自指输入：T-1 轮自指输入来自 T-1-N 轮的 decoder 输出。比较的是 T 轮与 T-1-N 轮的 decoder 输出。N 越大，差异越大，门控永远放行。
- 若比较 T 轮 decoder 输出与 T-N 轮自指输入：T-N 轮自指输入来自 T-2N 轮的 decoder 输出。比较的是 T 与 T-2N，更离谱。

**两层组合后，新颖性门控的逻辑基准完全错乱**。

### 3.3 第四层 × 既有在线熵管理：直接对冲

如 2.4 所述，第四层（coherence 高 → 注入噪声 → 升熵）与既有在线熵管理（entropy 高 → 增强正交化 → 降熵）在特定区间直接冲突。设计未定义优先级，可能导致每轮先注入噪声再增强正交化，系统在高频抖动中空耗算力。

### 3.4 第四层 × 既有元目的翻转：上下阈值的"无人区"

- coherence < 0.5：触发元目的翻转（既有）
- coherence > 0.95：触发噪声注入（第四层）
- 0.5 ≤ coherence ≤ 0.95：**无任何干预**

自指锁定很可能将 coherence 稳定在 0.7-0.9 的"无人区"——既不高到触发逃生阀，也不低到触发翻转。**七层设计最需要干预的区间，恰恰是所有机制都不生效的区间**。

### 3.5 第五层 × 第六层：做梦后的延迟缓冲区陈旧

做梦后恢复在线，延迟缓冲区仍存有做梦前的 decoder 输出。前 N 轮在线时，自指注入的是"旧网络的回声"。若做梦大幅修改了 J（SHY 归一化可能将 J 范数缩放到 10.0，`dream_engine.py:564`），旧 decoder 输出与新网络的语义完全脱节。

### 3.6 第七层 × 元可塑性：三重冻结

如 2.7 所述，第七层 + 元可塑性 lr 降低 + 第三层习惯化 = 深度冻结，无解冻路径。

## 四、新发现的风险场景清单

| # | 风险场景 | 严重度 | 是否被七层覆盖 |
|---|---------|--------|--------------|
| R1 | **负反馈振荡**：decoder 输出与当前状态反向（如"熵高"→系统降熵→"熵低"→系统升熵→...），形成周期振荡。七层全部针对正反馈死循环，无一层处理负反馈振荡。 | 高 | 否 |
| R2 | **自指信息泄露到长时记忆检索**：自指输入塑造 activation，activation 作为 `recall(activation.state)` 的线索（`loop.py:331`）。自指方向的 activation 会检索到自指强化的长时记忆，形成"自指回忆自指"的闭环污染。 | 高 | 否 |
| R3 | **情景缓冲区污染**：若自指文本被存入 `_episodic_buffer`（`loop.py:357`），`recall_episodic` 会返回自指文本作为"相关记忆回忆"注入 context，LLM 读到的是系统自说自话而非真实对话历史。 | 高 | 否 |
| R4 | **Decoder 的 surprise_history 污染**：`decoder.py:233` 的 `_record_surprise` 将每轮 surprise 存入历史。自指轮次的 surprise 进入历史后，`_interpret_surprise` 的均值比较被污染，"意外/吻合"解读失真。且 Decoder 状态**不在快照中持久化**。 | 中 | 否 |
| R5 | **快照恢复后的自指状态断裂**：`save_state` 不保存延迟缓冲区、新颖性历史、上一轮自指向量。恢复后自指回路冷启动，注入零向量或空信号到已学习的 J 上，引发瞬态扰动。 | 高 | 否 |
| R6 | **多会话自指独立性**：`SessionManager` 每个 session 独立 LivingMemoryLoop。若自指状态在 loop 内，各 session 自指独立——但这意味着自指无法跨会话积累。若期望跨会话连续性，需额外设计。当前未定义。 | 中 | 否 |
| R7 | **做梦后恢复瞬态**：做梦修改 J/precision/memory，延迟缓冲区存旧输出。恢复在线首 N 轮注入陈旧自指，可能触发大 surprise 和学习风暴。 | 高 | 否 |
| R8 | **Encoder-Decoder 往返损失导致的退化吸引子**：Decoder 输出是结构化文本（`"[记忆context]\n..."`），重新编码后向量代表文本骨架而非语义。反复往返会训练出一个"context 文本格式"的退化吸引子，占据网络容量。 | 中 | 否 |
| R9 | **空输入下自指独占**：用户输入为空、LLM 输出为空时，`text = user_input`（`loop.py:234`），sensory_input 可能为零向量。此时自指 0.3 是唯一信号，第一层阻尼失效。API 空闲轮询时可能出现此场景。 | 中 | 否 |
| R10 | **元可塑性 collapse_count 误判**：`meta.update` 的 `collapse_occurred = self.purpose.flipped`（`loop.py:317`）。元目的翻转被当作坍缩信号。自指可能导致频繁翻转（precision 不稳定），从而使 `temp_multiplier` 持续升高（`meta_plasticity.py:401`），温度无限攀升直至推断完全随机。 | 中 | 否 |
| R11 | **温度累积导致推断随机化**：若 R10 发生，`temp_multiplier` 可达 `bounds_max=2.0`，`effective_temp = 0.05 * 2.0 = 0.1`。结合第四层噪声注入，Langevin 扩散项 `sqrt(2*T)*noise` 幅度从 0.316 升至 0.447，激活态噪声增加 41%，推断质量下降。 | 中 | 否 |

## 五、架构层面的问题

### 5.1 自指回路应实现在哪一层？

**不应直接嵌入 `loop.py` 的 `process_turn`**。理由：

1. `process_turn` 当前是线性的 8 步流程，逻辑清晰。嵌入自指后，流程变为"编码（含自指混合）→ 推断 → 学习 → ... → 解码 → （捕获输出 → 编码 → 入延迟缓冲区）"，出现回路，线性阅读被破坏。

2. 自指回路有独立的状态（延迟缓冲区、新颖性历史、上一轮自指向量），这些状态不属于任何现有组件。

**建议**：新建独立模块 `runtime/self_ref_loop.py`，封装：
- 延迟缓冲区（deque）
- 新颖性比较逻辑
- 自指向量混合逻辑
- 与 DreamEngine 的断开/恢复钩子

通过两个钩子集成到 `process_turn`：
- **pre-encode 钩子**：在 `loop.py:235` 的 `encoder.encode` 之前，将延迟缓冲区的自指向量与外部感官向量混合。
- **post-decode 钩子**：在 `loop.py:352` 的 `decoder.decode` 之后，捕获 memory_context，重新编码，入延迟缓冲区。

这样 `process_turn` 的主体流程不变，自指是可插拔的横切关注点。

### 5.2 与 DreamEngine 的集成

DreamEngine 不调用 `process_turn`，天然断开。但需要：
- DreamEngine 开始前：调用 `self_ref_loop.on_dream_start()`，冻结/清空延迟缓冲区（按策略选择）。
- DreamEngine 结束后：调用 `self_ref_loop.on_dream_end()`，处理陈旧缓冲区（如清空或标记为"陈旧"降低权重）。

当前 `dream_engine.py` 和 `loop.py` 都没有这样的钩子。

### 5.3 与持久化的集成

`save_state` / `load_state` 需要扩展，保存自指回路状态：
- 延迟缓冲区（list of (text, vector, turn)）
- 新颖性历史
- 上一轮自指向量

`snapshot.py` 的 `save()` 需要新增可选字段 `self_ref_state`，版本号升至 0.4.0。

## 六、与现有机制的冲突

### 6.1 元可塑性的 surprise 趋势分析会被自指干扰

**会，且严重**。`meta_plasticity.py:319` 的 `_compute_lr_multiplier` 计算 surprise 的 EMA 趋势。自指锁定导致 surprise 持续下降，趋势为负，`lr_multiplier` 被压向 0.5。这降低全局学习率，不仅影响自指，也影响外部输入的学习——**自指通过元可塑性间接抑制了系统对外部真实输入的学习能力**。

更隐蔽的是：`meta.update` 的 `collapse_occurred = self.purpose.flipped`（`loop.py:317`）。若自指导致 precision 不稳定（频繁翻转），`collapse_count` 累积，`temp_multiplier` 升高，系统温度攀升，推断随机化。**自指的波动会被元可塑性误判为"坍缩频繁"，触发不必要的温度升高**。

### 6.2 在线熵管理"熵过高增强正交化"与"coherence 上阈值注入噪声"冲突

**直接冲突**，如 3.3 所述。两者在 `entropy_ratio > 0.9 且 coherence > 0.95` 的区间同时触发，一个降熵一个升熵。

此外，即使不同时触发，它们的**目标信号不同**（entropy vs coherence）意味着系统有两个独立的"稳定性干预者"，各自为政，缺乏协调器。七层设计没有定义这些干预机制的优先级和仲裁逻辑。

### 6.3 情景记忆缓冲区是否应该存储自指生成的文本？

**不应该**，但当前架构无法区分。

`loop.py:357` 的 `store_episodic` 存入的 `text` 是 `f"用户: {user_input}\n助手: {llm_output}"`。若自指回路在 pre-encode 阶段混合了自指向量，text 本身不含自指文本（自指是向量级混合，不是文本级）。但若自指回路采用"将 decoder 输出作为额外文本拼入"的方案，text 会包含自指内容。

**更深的问题**：即使 text 不含自指，`semantic_vector` 是对 text 编码的结果，而 `activation.surprise` 被自指影响。`store_episodic(text, semantic_vector, activation.surprise, ...)` 存入的 surprise 已被自指污染。后续 `consolidate` 按 surprise 排序回放（`memory.py:164`），自指轮次若 surprise 异常，会被错误地优先或延后回放。

**建议**：
- 情景缓冲区只存外部来源的文本（user + llm），不存自指文本。
- 为自指文本建立独立缓冲区（若需要），或在 `EpisodicEntry` 增加 `source: str` 字段区分 `'external'` / `'self_ref'`，检索时过滤。

## 七、测试策略的不足

### 7.1 100 轮远远不够

关键时间尺度：
- 习惯化：`habituation_rate=0.05`，需 ~40 轮使 precision 减半，~200 轮使 precision 降至 0.1。
- 元可塑性：`meta_interval=10`，需 ~60 轮（6 次元更新）才能使倍率从 1.0 平滑到目标值。
- 延迟反馈：N=3-5，需 ~15 轮才能形成完整延迟链。
- 巩固：`consolidation_interval=5`，需 ~50 轮才能观察到 10 次巩固的累积效应。

**建议**：最小测试时长 1000 轮，推荐 5000 轮。且必须包含"空输入"段（模拟 API 空闲）和"做梦插入"段。

### 7.2 缺失的监控指标

当前 `get_status()`（`loop.py:518`）只返回 turn_count / entropy / surprise / coherence / precision 统计。自指回路需要额外指标：

| 指标 | 定义 | 预警阈值 |
|------|------|---------|
| 自指贡献比 | `‖self_ref_vec‖ / ‖total_sensory‖` | 持续 < 0.05（功能死亡）或 > 0.5（失控） |
| 激活自相关（lag N） | `cos(σ_t, σ_{t-N})` | > 0.95 持续 20 轮（锁定）或 < -0.5（振荡） |
| J 范数漂移率 | `‖J_t - J_{t-100}‖_F / ‖J_t‖_F` | > 0.3（漂移过快） |
| coherence 分布 | 100 轮窗口内 coherence 的均值与方差 | 均值 > 0.9 且方差 < 0.01（冻结） |
| surprise 分布 | 100 轮窗口内 surprise 的均值 | |均值| < 0.01 × ‖J‖（坍缩） |
| 情景缓冲区自指污染率 | 自指来源条目数 / 总条目数 | > 0.2（污染） |
| 元倍率偏离 | `max(|lr_mult-1|, |orth_mult-1|, |temp_mult-1|, |cw_mult-1|)` | 持续 = 2.0（元机制饱和） |

### 7.3 缺失的应力测试场景

1. **纯自指**：1000 轮空用户输入，只有自指反馈。验证自指是否会自激振荡。
2. **重复输入**：1000 轮相同的用户输入。验证自指 + 重复输入是否导致超快锁定。
3. **振荡输入**：交替输入两个对立主题。验证自指是否放大振荡。
4. **做梦插入**：每 100 轮插入一次做梦，验证恢复瞬态。
5. **快照恢复**：运行 500 轮 → 保存 → 恢复 → 继续 500 轮。验证自指状态恢复的正确性。
6. **参数扫描**：自指权重 ∈ {0.1, 0.2, 0.3, 0.5, 0.8}，N ∈ {1, 3, 5, 10}，各跑 1000 轮。寻找稳定参数空间。

## 八、七层中哪些必须，哪些过度设计

| 层 | 评级 | 理由 |
|----|------|------|
| **第一层 反馈幅度阻尼** | **必须** | 没有它自指直接主导。但 0.3 需改为相对 `‖external‖` 的自适应比例，而非固定值。 |
| **第二层 新颖性门控** | **保留但需重设计** | 对慢漂移有效，但对振荡无效。比较基准需明确（用向量余弦，阈值接近 1.0）。 |
| **第三层 习惯化阻尼** | **已存在，非新层** | 这是 PurposeLayer 既有机制。复用即可，但需监测 encounter_count 单调增长导致的全局精度坍缩。这不是"新设计"，是"既有机制的副作用"。 |
| **第四层 熵逃生阀** | **过度设计，建议删除** | 与既有在线熵管理和 dream_engine 坍缩检测三重重叠。触发信号（coherence > 0.95）概念错位且几乎不可达。若保留，应改为基于"激活自相关"而非 coherence。 |
| **第五层 做梦断开** | **必须但低成本** | 天然成立（DreamEngine 不调用 process_turn）。只需增加延迟缓冲区的做梦前/后管理钩子。 |
| **第六层 延迟反馈** | **保留但需处理陈旧性** | 解耦即时反馈是合理的。但必须处理：冷启动填充、做梦后陈旧、快照恢复断裂。延迟输出应标记生成时的 turn_count，注入时按"年龄"衰减权重。 |
| **第七层 惊讶度门控** | **危险，建议删除** | surprise≈0 恰是自指锁定的稳态，跳过学习会保护这个稳态。与元可塑性三重叠加导致深度冻结且无解冻路径。若要防止过度学习，应改为"学习率随 surprise 平滑衰减"而非硬性跳过。 |

**总结**：七层中，**第一、五层必须；第二、六层保留但需修复；第三层是既有机制的复用（不算新层）；第四、七层建议删除**。真正的自指稳定性不应靠堆叠七层补丁，而应靠**一个协调的、基于自相关监测的反馈控制环路**。

## 九、建议的改进措施

### 9.1 用"自指自相关监测器"替代第四层和第七层

新增一个监控指标：`autocorr_lag_N = cos(σ_t, σ_{t-N})`。

- `autocorr > 0.95` 持续 K 轮 → 判定为"锁定"，执行：降低自指权重（动态阻尼）+ 注入正交噪声到 sensory（不是 J）。
- `autocorr < -0.3` 持续 K 轮 → 判定为"振荡"，执行：降低自指权重 + 增大延迟 N。
- 正常区间 → 恢复自指权重。

这比 coherence 和 surprise 更直接地衡量"自指回路自身的稳定性"。

### 9.2 自指权重改为自适应

固定 0.3 在所有工况下都不合适。建议：

```python
self_ref_weight = base_weight * (1 - autocorr_clipped)  # autocorr ∈ [0, 1]
```

锁定时 autocorr→1，权重→0（自动静默）；发散时 autocorr→0，权重→base（恢复自指）。

### 9.3 延迟缓冲区纳入持久化 + 做梦钩子

- `save_state` / `load_state` 增加 `self_ref_buffer` 字段。
- DreamEngine 开始前调用 `self_ref_loop.on_dream_start()`：将缓冲区标记为 `stale=True`。
- 恢复后注入时，`stale` 条目的权重乘以衰减因子 `exp(-age / tau)`。

### 9.4 情景缓冲区增加来源标记

`EpisodicEntry` 增加 `source: str = 'external'` 字段。`recall_episodic` 增加 `source_filter` 参数，默认只检索 `'external'`，防止自指文本污染 LLM 可见的 context。

### 9.5 自指学习隔离

自指轮次的 `learn()` 调用应使用**独立的学习率**（低于外部输入的学习率），且不触发元可塑性的 surprise 更新（防止自指 surprise 污染元参数趋势）。具体：在 `process_turn` 中增加 `is_self_ref_turn` 标志，`meta.update` 时跳过自指轮次的 surprise 采样。

### 9.6 统一的稳定性仲裁器

七层散落在不同组件中，缺乏协调。建议在 `runtime/self_ref_loop.py` 中实现一个 `StabilityArbiter`，汇总所有稳定性信号（autocorr、entropy、coherence、surprise、autocorr），统一决策自指权重的调整，避免多机制对冲。

## 十、结论

七层设计的**出发点正确**（自指回路确实需要稳定性保障），但**实现路径存在系统性问题**：

1. **信号选择不当**：用 coherence（目的稳定性）和 surprise（自由能）作为自指稳定性的代理指标，两者都不直接反映"自指回路自身的动力学"。应改用激活自相关。

2. **层间缺乏协调**：七层各自独立判断，无仲裁机制，存在直接对冲（第四层 vs 在线熵管理）和三重冻结（第七层 × 元可塑性 × 习惯化）。

3. **只防正反馈，不防负反馈**：七层全部针对"自指锁定/死循环"，无一层处理"自指振荡"。

4. **状态管理缺失**：延迟缓冲区、新颖性历史等自指状态未纳入持久化和做梦钩子，导致快照恢复和做梦后恢复的瞬态风险。

5. **过度依赖魔法数字**：0.3、0.95、N=3-5 等参数均无理论或实验依据，且未提供调参方法论。

**核心建议**：删除第四、七层，将第一、二、六层整合为一个基于自相关监测的自适应反馈控制器，第三层复用既有习惯化机制但加入"自指/外部来源区分"，第五层补充做梦钩子。最终从"七层补丁"收敛为"一个协调的自指控制器 + 既有机制复用"。
