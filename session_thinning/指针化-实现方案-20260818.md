## 〇、结论先行

1. **指针化的成立形态 = 分级解引用，不是字面版"最近 K 轮全换指针"。** 薄化方案 §2.2 已裁决：
   「当前轮+指针」字面版丢任务连续性/工具链因果/多轮意图，工程上不可行。成立版是
   **三段式内再分级**：最近 `K0` 轮原文**逐字保留**（工具链工作记忆安全网，§2.2 的
   "最近 K 轮原文"就是为保它）；`(K0, K]` 轮原文降级为**指针行**（JSONL/事件流锚点 +
   摘要），需要时按标准读路径解引用展开；`> K` 轮为步骤1 的单一 checkpoint 摘要。
   ——指针化不删历史、不破坏工具链，只是把「常驻逐字」换成「锚点 + 按需展开」。
2. **任务状态对象 = B 段动态注入的「意图连续性」载体**（薄化方案 §四 形态修正：
   任务状态机提供意图连续性，记忆检索提供事实连续性，制品层提供产出连续性）。
   载体 = 任务书/goal 对象的结构化文件（现任务书文件已事实承担此角色，本次将其结构化）
   + 事件流发布；每轮结束更新、任务完成归档为记忆条目。
3. **全部改动点落在 OpenClaw 会话层内核**（context-engine 装配钩子 / /compact /
   系统提示装配 / 注入消费端 / env 接线）——逐条登记 `integration_points.json`
   （13 条，全部 `status=待集成`、`blocker=需主代理确认，不擅改环境`），
   带文件/钩子/锚点定位。本文件不改任何既有文件、不写任何 OpenClaw 侧代码。
4. **验证沿用步骤0 的 measure 口径**（`measure.analyze_context`：四段占比 /
   window_usage_ratio / pressure_level / required_cut_chars），每步开关前后各采一份
   ContextSample 对比；验收判据见 §三.2。灰度旋钮统一 `LMS_SESSION_*` 命名、默认全关。
5. **目的五问**：Q1 流动 / Q2 过程 / Q3 活体 / Q5 可回放 均「必须-满足」；
   Q4 熵核不涉及熵决策，本方案**保留现有 LMS 注入与惊讶信号管线原样**、只改载体，
   不破坏薄化方案 §5.2 的检索质量前置（且时序上排在弥散态修复之后）——「满足」。
   详见 §五，无 purpose-drift 登记。

## 一、步骤3 指针化（总任务书 §二.7；薄化方案 §三 步骤2）

### 1.1 目标与边界

- **改什么**：transcript 尾部 `(K0, K]` 轮原文在模型面（surface）的呈现形态——从
  「逐字重放」改为「指针引用」；`≤ K0` 轮保持逐字（工具链工作记忆）；`> K` 轮保持
  步骤1 的 checkpoint 摘要。
- **不改什么**（薄化方案 §2.3 对策铁律）：① 静态锚 A 段（系统提示/身份/工具规则）
  不动；② 记忆存储与检索管线（LMS 六层注入的检索逻辑）不动，只可能在其注入条目的
  呈现上追加来源指针（见 §1.5 注入条目指针化）；③ 磁盘上的原文历史永不因指针化删除
  （指针化只动模型面，原文库是 durable 载体）。

### 1.2 指针指向什么（载体三选 + 指针形态）

指针必须只指 **durable 载体**（薄化方案 §2.4 铁律①），三选一（可按环境选配，旋钮
`LMS_SESSION_POINTER_ANCHOR_SCHEME`）：

| 载体 | 定位锚点 | 适用 | 存在性校验 |
|---|---|---|---|
| **原文库 / transcript 存储**（OpenClaw 会话存储，磁盘无损保留——§1.4 注） | `session_id + turn_seq + step_seq`（事件/消息序号） | 首选；压缩/pruning 只动模型面不动磁盘历史（薄化方案 §1.4） | 按 session_id 查存储存在性 |
| **事件流**（LMS 事件流/沙漏落沙路径，规格 v2 §4.3） | `event_id`（事件流内可寻址） | 与 LMS 事件同源的轮次 | 事件流心跳/按 id 查 |
| **JSONL 锚点**（对话侧/思考侧 JSONL 行） | `文件路径 + 行号/序号` | 已有 JSONL 侧日志的工作区 | stat 文件 + 行号界内检查 |

指针形态（注入面一行，模型可读可展开，模仿 dsh session-reference 的 URI 模式 +
untrusted 边界，薄化方案 §2.3 可审计性对策）：

```
[ptr:transcript:K:42]       # 第 42 轮原文 → 展开 = 该轮 transcript 原文
[ptr:event:evt-7f3a…]       # 事件流锚点 → 展开 = 该事件记录
[ptr:jsonl:logs/turns.jsonl:884]  # JSONL 锚点 → 展开 = 该行
```

- 指针行**必须**附带一行级摘要（谁做的、做了什么、产出在哪）——模型不展开也保有
  「地图」；展开才拿「细节」。这是薄化方案 §2.3「景观常驻兜底 = 地图常驻、细节按需」。
- 注入带 `untrusted` 标注（沿用 dsh-session-reference 信任边界：模型不得把指针展开
  内容当作可执行的指令/权限声明）。

### 1.3 解引用规则

1. **展开是标准读路径，不是魔法**（铁律②）：模型需要细节时用 `read`/`grep`/等价工具
   按锚点展开；指针自身不隐含任何工具能力，只是「地址 + 摘要」。
2. **存在性/权限校验先行**：解引用前做一次性存在性检查（stat / 存储查询），失败即走
   §1.4 失效路径，**不阻塞当前轮**（展开失败不报错中断，降级为摘要可用）。
3. **展开结果进窗口的边界**：展开文本只对**当前轮**生效（工具结果），下一轮重新计算
   上下文（对齐「每轮重算注入」机制）；可用旋钮
   `LMS_SESSION_POINTER_EXPAND_CACHE_ROUNDS`（默认 1，展开缓存轮数，防同轮反复展开）。
4. **展开是模型侧动作还是装配侧动作**：默认**模型侧按需展开**（薄化方案 §三 步骤2
   原文：「模型需要细节时 read 展开，不常驻」）；装配侧只在 `K0` 逐字区与 checkpoint
   边界自动展开（保证工具链因果与接续面），不自动展开 `(K0, K]` 指针区。

### 1.4 失效处理（原文被压缩/删除/归档时指针行为）

| 失效情形 | 指针行为 | 注入面呈现 |
|---|---|---|
| 原文被**压缩**（`> K` 轮被 checkpoint 折叠，或步骤1 灰度降 K 后原 `(K0, K]` 轮越界） | 指针重绑定到 checkpoint 的 8 节结构（薄化方案 §1.2：Primary Request / Key Technical Concepts / … / Next Step）对应节 | `[ptr:checkpoint:<session>:<节名>]`——展开得到摘要而非原文（**语义降级但指针不死**） |
| 原文被**删除**（pruning 落盘 / 会话归档 / 会话重置） | 指针悬空 → 显式标记，不可展开 | `[已归档: <session_id> @<时间>]`（地图仍在：时间/位置可寻，原文不可得） |
| **权限不可达** | 同「已归档」处理 | `[不可达: <原因>]` |
| **解引用失败/超时** | 一次性失败走降级路径，不重试轰炸、不阻塞当前轮 | 保持摘要行可用 |

- **铁律**：不允许「未声明的悬空」——任何不可展开的指针都必须在注入面显式标注
  （验收判据 V4：未声明悬空 = 0）。指针生命周期钩子挂在 transcript 压缩/pruning
  路径上（集成点 A-PTR-03）。
- **多轮意图兜底**：指针只指 durable 载体（存储/事件流/文件），**不指会话内消息
  序号**（会话滚动/重置会让会话内指针失效——薄化方案 §2.2 记忆 1–4 的失忆感教训）；
  transcript 轮序号只是同一 durable 原文库内的定位键。

### 1.5 K 轮灰度与步骤1/2 的关系

- **与步骤1（K 轮压缩）的关系**：步骤3 的裁剪对象就是步骤1 保留的 K 轮尾部原文。
  步骤1 回答「多少轮原文在窗口」（700 → K，K 灰度 50→30→20）；步骤3 回答「在窗口的
  原文以什么形态呈现」（K 轮 → `K0` 逐字 + `(K0, K]` 指针）。**步骤3 不改变 K 值**，
  只改变呈现形态；步骤1 必须先稳定（K band 走完），步骤3 才可开（一次一变量）。
- **K0 参数**：`(K0, K]` 区间的边界。K0 = 工具链工作记忆强制逐字轮数（安全下限 3–5，
  对齐薄化方案 §2.2「K 取 20–50」内的近尾工作记忆）。灰度从 **K0=8 起逐档降到 5、3**
  （指针化范围从小到大，安全方向）；K0 ≥ 3 与验收判据 V5（工具链回读 100%）绑定。
- **与步骤2（注入条目指针化，薄化方案 §三 步骤2）的关系**：注入条目指针化是
  **低风险先行**——只改 LMS/glue 注入条目的呈现（条目 id + 可展开全文路径，如
  `[mem:<entry_id>]`），不动 transcript 装配，只读可观测；transcript 尾部指针化
  （本步骤核心）风险更高，排在注入条目指针化**之后**灰度。两条共享同一套
  解引用/失效/标注机制（`interfaces.py` 的 `ArtifactPointer` / `POINTER_KINDS` /
  `expand_pointer`）。
- **灰度序（合并步骤1+3）**：
  `步骤1 K：50 → 30 → 20 稳定` → `注入条目指针化开`（观测 N 轮）→
  `尾部指针化 K0：8 → 5 → 3`（每档观测 N 轮，无退化再下一档）。

改动点全部登记 `integration_points.json`，此处给出钩子级说明（OpenClaw 具体文件路径
TBD——需主代理在 OpenClaw 侧确认）：

## 二、任务状态对象（总任务书 §二.7 步骤4；薄化方案 §三 步骤3）

### 2.1 目标与边界

- **改什么**：「任务进行中」的多轮状态（我们在做什么、做到哪、下一步、悬案、踩过的
  坑）从**散在 transcript** 提到**独立状态对象**，作为 B 段动态注入的一部分每轮重算
  注入——替代 transcript 提供的「线程感」（薄化方案 §三 步骤3 原文）。
- **不改什么**：任务书文件作为唯一权威的现状**不变**（薄化方案 §四 前提 1：任务书/
  goal 对象 + 工作区文件 + Git 为唯一权威）；本步骤是把任务书承载的状态**结构化 + 可
  注入 + 可归档**，不另立权威源。记忆存储/检索管线不动。

### 2.2 Schema（JSON，对齐 `interfaces.py` 前向声明的 `TaskState`）

```json
{
  "schema_version": 1,
  "task_id": "A-薄化",
  "goal": "总任务书 §二.7：会话层薄化四步（OpenClaw 侧）",
  "objective": "指针化 + 任务状态对象：出实现方案 + 标记待集成点",
  "progress": {
    "step": 3,
    "phase": "方案交付",
    "done": ["步骤0 测量拆分", "步骤3+4 实现方案与集成点标记"],
    "next": ["主代理确认集成点后实施"],
    "percent": 40
  },
  "todo": [
    {"id": "T1", "item": "步骤0 测量拆分", "status": "done"},
    {"id": "T2", "item": "步骤3 指针化实现方案", "status": "done"},
    {"id": "T3", "item": "OpenClaw 集成确认", "status": "blocked", "blocker": "需主代理确认，不擅改环境"},
    {"id": "T4", "item": "实施与验证", "status": "pending"}
  ],
  "open_questions": [
    {"id": "Q1", "question": "OpenClaw context-engine 槽的具体文件路径", "status": "pending"}
  ],
  "linked_memory": [
    {"kind": "memory", "id": "<LMS 条目 id>", "rel": "evidence"},
    {"kind": "artifact", "id": "rewrite-ws/session_thinning/measure.py", "rel": "outcome"},
    {"kind": "session", "id": "<OpenClaw session id>", "rel": "context"}
  ],
  "updated_at": "2026-08-18T19:00:00+08:00",
  "updated_by": "四妹/子代理 <id>",
  "source": "总任务书-重编一口气-四妹-20260818.md §二.7"
}
```

字段语义：`task_id`（任务唯一键，跨会话可寻）；`goal/objective`（意图连续性，注入
顶部）；`progress`（阶段/完成/下一步/百分比）；`todo`（待办清单，含 `blocked` 与
`blocker` 原因——悬案显式化）；`open_questions`（悬案登记：问题 + 状态，防散在
transcript 丢失）；`linked_memory`（关联记忆/制品/会话，双向可检索）；`updated_at /
updated_by`（审计与唯一写者）；`source`（权威来源文件路径）。

### 2.3 生命周期（创建 / 更新 / 归档）

1. **创建**：任务开始/任务书发布时实例化（从任务书文件初始化 `task_id/goal/
   objective`）。创建即发布事件流事件（规格 v2 §4.3：落沙路径同时发布事件）。
2. **更新**：**唯一写者**（对齐 M5 状态管理清单纪律：每对象一个写侧站点）——每轮
   结束/每步完成时由任务执行侧（子代理报告集成处/工具链末端钩子）更新
   `progress/todo/open_questions/linked_memory/updated_at`；每次更新发布事件流事件。
   检索/注入时相只读投影，不写（对齐只读四不变纪律）。
3. **归档**：任务完成 → 归档为**记忆条目**（事件流发布 + LMS store 写侧 ingest，
   规格 v2 §2 ingest 语义），供未来任务检索（经验/教训/产出），同时从常驻注入中移除
   （防死档案常驻）。归档不删除：对象文件保留为审计记录。

### 2.4 与 LMS 记忆/注入的衔接

- **B 段注入成员**：任务状态对象与 LMS 记忆检索、景观、时间同属「每轮重算的动态
  注入」（薄化方案 §二.2 B 段）——注入面为「当前任务指针块」（§2.5 注入顶部），
  内容 = `task_id + goal + progress + next + open_questions 摘要`，占窗口小。
- **三连续性分工**（薄化方案 §四 形态修正）：任务状态对象 = 意图连续性（为什么在做）；
  LMS 记忆检索 = 事实连续性（上次修到哪、踩过什么坑）；制品层（文件/Git）= 产出
  连续性（代码/文档现状）。**三者互补，任务状态对象不替代记忆检索**。
- **活体衔接**：状态更新事件流 → LMS 可感知（事件驱动，规格 v2 §4.3 坑 7 根治方向：
  事件流不断流）；任务完成归档 → 写侧 ingest → 未来检索可得——「任务状态对象有
  生命周期、记忆/上下文机制真在动」。
- **检索质量前置不变**：任务状态对象只注入**结构化事实**（不依赖检索质量），
  但记忆检索注入仍按薄化方案 §5.2 时序（弥散态修复后）——两条注入路径解耦。

### 2.5 OpenClaw 侧改动点（模块/钩子/接口）

| 改动点 | 钩子/接口 | 集成点 id |
|---|---|---|
| 任务状态对象载体与 schema 落地 | `interfaces.py` 前向声明的 `TaskState` / `load_task_state` / `save_task_state`（rewrite-ws 侧接口）+ 对象文件载体（任务书同目录/工作区） | A-TSK-01 |
| 注入系统提示顶部（当前任务指针块） | 系统提示装配（静态锚 A 段顶部追加）/ harness runtime-context 注册表模式（薄化方案 §一.3：注册表 + 每步求值 + 来源标注）或 OpenClaw directive 机制 | A-TSK-02 |
| 状态更新钩子 + 事件流发布 | 每轮结束/子代理报告集成处的写侧钩子；LMS 事件流发布（规格 v2 §4.3 同源） | A-TSK-03 |
| 完成归档为记忆条目 | LMS store 写侧入口（ingest 语义）+ 事件流 | A-TSK-04 |

### 2.6 回滚方式

- `LMS_SESSION_TASKSTATE_ENABLED=0`：任务状态对象停止注入/更新，恢复「线程感靠
  transcript」现状（K 轮逐字仍在，不丢连续性）；对象文件保留不删。
- 二级回滚：连同 `LMS_SESSION_POINTERIZE_ENABLED=0` 回到步骤1 形态。

## 三、验证方案

### 3.1 对照步骤0 的 measure 口径

- 每次验证采集一份 **ContextSample**（四段字符数：`transcript_chars /
  lms_injection_chars / tool_schema_chars / system_prompt_chars` + `model_window`），
  经 `session_thinning.measure.analyze_context` 得：各段 `share` / `window_occupancy` /
  `window_usage_ratio` / `pressure_level` / `required_cut_chars` / `trim_priority`。
- 采样在 OpenClaw 侧执行（`/context detail` + `/status`，集成点 A0-MEAS-01；
  measure.py docstring 已声明该待集成点——需主代理确认，不擅改环境）。
- **对比设计**：同一会话、同一轮次，旋钮开关前后各采一份；记录到验证日志
  （可回放：日期 + session id + 旋钮值 + 两份分析 JSON）。

### 3.2 分步验证与验收判据（步骤3 每子步）

| 判据 | 测量方法 | 阈值 |
|---|---|---|
| V1 指针化生效 | 开关前后 `transcript` 段 `chars`/`share` 对比（§3.1） | transcript 段占用率下降 ≥ 70% |
| V2 窗口占用率 | `window_usage_ratio`（步骤1+3 合计） | ≤ 40%（对齐薄化方案 §三 预期 30–40%） |
| V3 解引用成功率 | 随机抽 100 个指针，按 §1.3 标准读路径展开 | 成功率 ≥ 95% |
| V4 未声明悬空 | 扫描注入面指针 + 失效日志（§1.4） | 未声明悬空 = 0（全部走显式降级路径） |
| V5 工具链因果不断 | `K0` 轮内前序轮的工具结果回读（模型答「上一步的路径/错误串/中间值」） | K0 轮内回读正确率 100% |
| V6 任务状态注入可见 | 系统提示顶部任务指针块存在；模型可答「当前任务/进度/下一步/悬案」 | 3/3 问题答对 |
| V7 回归不劣化 | P0-2 命中率 / 判读质量 / 审计漏检率（八荣八耻灵魂指标） | 与基线持平或更优 |
| V8 一次一变量 | 观测窗口内 B 级 24h 观察 / P1-4 实施无并发 | 无并发记录 |

### 3.3 灰度开关（env 旋钮，`LMS_SESSION_*` 命名）

> 命名对齐 .env.example 规范（模块前缀 + 下划线，单一默认值来源 = 各模块 docstring，
> 规格 v2 §5.3）；默认全部关闭（验证链纪律：默认保守、显式开启）。步骤1 的旋钮
> 由（待落地的）`compression.py` docstring 定义（前向声明 `k_from_env` /
> `mode_from_env` / `should_enable`）；本表步骤3/4 旋钮若与步骤1 落地名冲突，以
> compression.py 的单一默认值来源为准。

| 旋钮 | 默认 | 语义 |
|---|---|---|
| `LMS_SESSION_POINTERIZE_ENABLED` | 0 | 步骤3 尾部指针化总开关（0 = 步骤1 形态：K 轮逐字） |
| `LMS_SESSION_POINTER_K0` | 3 | 工具链工作记忆强制逐字轮数（灰度 8 → 5 → 3；≥3 与 V5 绑定） |
| `LMS_SESSION_POINTER_KEEP_K` | 20 | 与步骤1 K band 对齐（继承 50→30→20 当前档） |
| `LMS_SESSION_POINTER_ANCHOR_SCHEME` | `transcript` | 指针载体：`transcript` \| `eventstream` \| `jsonl` |
| `LMS_SESSION_POINTER_EXPAND_CACHE_ROUNDS` | 1 | 展开结果缓存轮数（防同轮反复展开） |
| `LMS_SESSION_TASKSTATE_ENABLED` | 0 | 任务状态对象注入/更新总开关 |
| `LMS_SESSION_TASKSTATE_FILE` | 空 | 任务状态对象文件路径（空 = 不启用文件载体） |
| `LMS_SESSION_TASKSTATE_EVENTS` | 0 | 状态更新发布事件流（活体衔接） |
| `LMS_SESSION_VERIFY_LOG` | 空 | 验证日志路径（§3.1 可回放记录） |

### 3.4 已知风险与对策

| 风险 | 对策 |
|---|---|
| **检索噪声放大**（precision_mean≈0.28 时注入是主要事实来源） | 注入管线原样保留、只改载体；时序上排在弥散态修复（P0-2/A 级）之后（薄化方案 §5.2） |
| **指针失效/展开成本** | 铁律① durable 载体 + 铁律② 标准读路径；存在性校验先行；失效显式降级（§1.4） |
| **工具链因果断裂**（K0 太小） | K0 ≥ 3 安全下限；V5 验证绑定；灰度从 K0=8 起 |
| **语义漂移**（长期一致性弱化） | 身份层/静态锚 A 段不动；任务状态对象保意图连续性（§二.4） |
| **双近似叠加**（压缩有损 + 注入噪声） | 承认双近似；红利 = 每轮预算可控 O(注入预算)；V7 回归把关 |
| **行为基线漂移污染 B 级归因** | 一次一变量（V8）：与 B 级观察、P1-4 错开变量窗口（薄化方案 §5.2） |
| **可审计性下降**（模型为什么知道/不知道 X） | 指针带锚点（id/载体/摘要），注入带 untrusted 来源标注；验证日志可回放（Q5） |
